# TranscriptX v0.1 canonical contract (short)

**Scope:** This note captures a few runtime assumptions that are easy to miss in code review. It is **not** a migration guide and does **not** supersede the authoritative contracts:

- Storage and admission → [`docs/runtime/STORAGE.md`](runtime/STORAGE.md)
- Run execution truth → [`docs/run_outcome_contract.md`](run_outcome_contract.md)
- Output layout and manifests → [`docs/contracts/output-contract-v1.md`](contracts/output-contract-v1.md)

If anything here conflicts with those documents, the linked contracts win.

## Transcript after load (in-memory)

- Segments carry **text**, **timing**, and **speaker labels** as produced by the pipeline or loaders that feed it.
- **Emotion / NER enriched segments** may expose both canonical keys and **parallel keys** used by tests or downstream charts (for example `context_emotion` alongside NRC-style fields). Those duplicates are **intentional output shape**, not silent migration.
- **Speaker map parameters** on analysis entrypoints may be accepted but **ignored** where the module does not use them; callers should not rely on them for core behavior.

## `run_results.json`

- Canonical execution truth uses **`schema_version >= 2`**; typed loaders reject older schemas. See [run_outcome_contract.md](run_outcome_contract.md) for status vocabulary, write/read ordering, and projection rules.
- Prefer **`load_run_results`** / **`load_run_outcome_context`** instead of ad-hoc JSON parsing for truth-path consumption.

## Manifest (`manifest.json`)

- Records provenance, artifact index, and reproducibility metadata alongside runs. **`RunManifest`** fields include hashes, module versions, and optional config snapshot references; treat the manifest as the **artifact registry**, not the sole source for execution status (status projection stays with `run_results`).

## Speaker identity

- Segments use **string speaker ids** as assigned during processing; **`speaker_db_id`** / **`original_speaker_id`** (when present) are **stable linkage fields** for persistence and UI, not duplicate “legacy” speakers.
- **`speaker_map`** in fixtures or optional parameters is **deprecated for new call sites** but may remain on signatures where tests or batch tooling still pass it.

## Configuration

- **Strict JSON and env**: unknown top-level sections, removed dashboard keys (`overview_chart_types`), legacy audio shapes, and deprecated `TRANSCRIPTX_AUDIO_*_ENABLED` env vars **fail load** with **`ConfigLoadError`** and a **migration-directional** message (see `config_raw_validation.py`).
- There is **no** `Config` alias on the package; use **`TranscriptXConfig`**. Flexibility for odd on-disk shapes belongs at **explicit import/IO adapters**, not in silent config rewriting.

## Import-boundary flexibility

- **Vendor JSON**, **Whisper-class exports**, and **filesystem layout** may be normalized **only** in dedicated IO/adapters. Core pipeline and config loading do not apply silent coercions or “best effort” upgrades.
